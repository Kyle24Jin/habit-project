# Habit Tracker MVP 需求说明文档 (PRD)

## 1. 产品简介
Habit Tracker 是一款专注于个人习惯养成与追踪的轻量级应用。旨在通过极简的界面、流畅的交互以及直观的数据统计，帮助用户建立并保持良好的日常习惯。

## 2. 目标用户
希望改善生活作息、培养新技能或坚持锻炼的个人用户，且偏好轻量、无干扰的记录方式。

## 3. 核心功能模块

### 3.1 习惯管理 (Habit Management)
- **预设习惯**: MVP 阶段系统将内置 3-5 个常用习惯（如：早起、阅读 30 分钟、喝水 2L、运动）以便直接体验功能。
- **自定义习惯**: 支持简单的新增自定义习惯。
- **习惯状态**: 每个习惯具有活跃/归档状态。

### 3.2 每日打卡 (Daily Check-in)
- **主界面 (Today)**: 展示当天的日期与问候语。
- **列表展示**: 列出今日所有需要完成的活跃习惯。
- **快捷打卡**: 提供一键（Toggle 或 Checkbox）完成打卡的操作。
- **视觉反馈**: 打卡成功后，应有明确的状态变化（柔和色彩、打钩动效、轻微回弹触感）。
- **今日进度**: 在页面顶部显著展示今日习惯完成度（环形/条形进度展示）。

### 3.3 数据统计 (Statistics)
提供专门的面板查看历史表现，包含三个维度的聚合展示：
- **按周统计 (Weekly)**: 
  - 柱状图或条形图，展示最近 7 天每天的习惯完成数量/比例。
- **按月统计 (Monthly)**: 
  - 月历视图，每天的格子根据当天的完成度显示不同深浅的颜色（热力图风格）。
- **按年统计 (Yearly)**: 
  - 类似 GitHub 提交记录的年度热力图，直观展示全年的坚持情况。

### 3.4 数据持久化 (MVP 限定)
- 用户的所有打卡记录和习惯列表变更必须保存在本地浏览器缓存中（`LocalStorage`）。
- 刷新页面或重新打开应用，数据不丢失。
- 架构上使用 Mock API Service 封装，预留未来无缝对接真实后端的能力。

## 4. 非功能性需求 (UI/UX 规范)
- **设备适配**: 优先考虑 Mobile-First（移动端优先）设计，同时完美兼容桌面端居中浏览。
- **视觉风格**: 极简 iOS 风格（Minimalist）。
  - 大圆角 (`border-radius: 16px` 及以上)。
  - 柔和的卡片阴影与背景灰度对比。
  - 清晰、无衬线字体排版。
- **离线与 PWA**: 支持添加至手机桌面，隐藏原生浏览器导航栏，提供沉浸式体验。

## 5. 验收标准 (Acceptance Criteria)
1. **可用性**: 用户可以在浏览器中打开页面，看到当天的任务列表，点击打卡后进度条实时更新。
2. **持久性**: 打卡后刷新网页，之前打卡的状态依然保留。
3. **统计准确性**: 切换到统计页面，能准确看到周/月/年三个维度的完成统计数据。
